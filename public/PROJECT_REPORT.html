Chapter 1: Executive Summary & Project Introduction

1.1 Company Background & Manufacturing Profile

Hari Engineering Works is an established precision engineering establishment headquartered in Sakinaka, Mumbai, Maharashtra. The organization manufactures high-performance industrial air moving machinery, air handling systems, and environmental air pollution control equipment. Its equipment portfolio includes heavy-duty Centrifugal Blowers (delivering up to 95,000 CFM), High-Pressure Combustion Air Blowers (up to 1,800 mm WG static pressure), Direct-Drive & Bifurcated Tube Axial Fans, Automated Pulse-Jet Bag Filter Dust Collectors, PP/FRP Chemical Wet Scrubbers, and custom Galvanized Iron / Mild Steel / Stainless Steel industrial duct networks.

1.2 Motivation for Digital Transformation

Historically, the industrial air moving equipment manufacturing sector has relied upon static physical brochures, manual telephone consultations, and paper-based engineering quotation drafting. This operational model suffered from significant friction points:

  • Protracted Sizing Cycles: Prospective clients spent 24-48 hours waiting for engineering sales reps to manually calculate fan static pressure duty points.
  • Order & Enquiry Opacity: High-value machinery procurement orders lacked real-time token tracking mechanisms.
  • Catalog Maintenance Inefficiency: Updating technical ratings, dimension charts, and field installation visuals required hardcoded source adjustments.

The Hari Engineering Works Digital B2B Platform resolves these challenges by providing a full-stack, enterprise-grade digital solution unifying an interactive product catalog, an automated Blower Selector aerodynamic calculator, tokenized order tracking, and an authenticated administrative Content Management System (CMS).

2.1 Three-Tier Architecture

The platform follows an enterprise Three-Tier architectural pattern:

2.2 High-Availability Zero-Downtime Fallback

To prevent business interruption during cloud database connectivity drops or DNS resolution delays, the application incorporates an autonomous in-memory fallback mechanism. If MongoDB Atlas is unreachable, the system automatically activates FALLBACK_PRODUCTS without crashing or serving HTTP 500 errors. 

// config/db.js connection resilience strategy
try {
  const conn = await mongoose.connect(process.env.MONGO_URI, options);
  console.log(`[Database] Connected: ${conn.connection.host}`);
} catch (error) {
  console.warn('[Database Warning] Connection failed. Activating autonomous Fallback Mode.');
  // App continues serving full catalog via productController.FALLBACK_PRODUCTS
}

Chapter 3: Mathematical Formulations & Blower Selector

3.1 Aerodynamic Physics & Duty Point Equations

The Blower Selector utility (public/js/blower-selector.js) computes required fan horsepower and recommends models based on fundamental fluid mechanics:

1. Volumetric Airflow Conversion:
Q (m³/h) = CFM × 1.69901
Q (m³/s) = Q (m³/h) / 3600

2. Static Pressure Head Conversion:
ΔP (Pascals) = mm WG × 9.80665

3. Theoretical Air Power:
P_air (kW) = [ Q (m³/s) × ΔP (Pa) ] / 1000

4. Recommended Motor Shaft Power:
P_motor (kW) = [ P_air / (η_fan × η_drive) ] × S_margin
Where η_fan = 0.70-0.85, η_drive = 0.95 (direct) or 0.90 (belt), S_margin = 1.15 (15% reserve).

3.2 Performance Curve Enveloping

The calculated operating duty point is compared against the catalog database. The engine evaluates: minAirflow ≤ Q ≤ maxAirflow and maxStaticPressure ≥ RequiredPressure, filtering by Centrifugal or Axial fan geometry and presenting the top matching models to the user.

Chapter 4: Multi-Channel Tokenized Request System

4.1 Request Classification & Prefix Architecture

Inbound communications are segmented into distinct request classes with standardized token identifiers:

Token Prefix Request Classification Operational Workflow & Business Urgency
P000000 Direct Purchase Order High-priority equipment order containing quantities, tax details, and delivery timelines.
RFQ000000 Request For Quotation Technical bid specifying airflow CFM, static pressure, gas medium, and duty point.
E000000 General Equipment Enquiry Product inquiry regarding model availability, dimensions, or technical brochures.
S000000 Turnkey Service Request On-site ductwork erection, dynamic balancing, or annual maintenance (AMC).

4.2 Customer Self-Service Tracking Portal

Clients query their assigned token at /track. The interface retrieves lifecycle milestones from /api/enquiries/track/:tokenNo, displaying real-time stages: Pending Review → Technical Evaluation → In Production → Dispatched.

Chapter 5: Administrative CMS & Portal Security

5.1 Real-Time KPI Metrics Dashboard

The protected administrative dashboard (/admin) provides high-level metrics:

  • Total Inbound Leads: Aggregate interaction volume.
  • Commercial Orders: Count of unprocessed P-prefixed commercial purchase orders.
  • Active RFQ Quotations: Engineering bids awaiting quotation review.
  • Live Machinery Listings: Number of equipment models active on the public catalog.

5.2 Security Infrastructure

The portal enforces enterprise-grade security controls:

  • Cryptographic Password Salting: Passwords hashed using bcryptjs with 10 salt rounds.
  • Stateless JWT Authentication: HMAC-SHA256 signed bearer tokens with session expiration.
  • HTTP Header Hardening: Protection against XSS, clickjacking, and MIME sniffing via helmet.
  • Strict Input Sanitization: Client and server parameter validation preventing NoSQL injection.
